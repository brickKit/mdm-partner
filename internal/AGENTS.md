# internal/：业务模块

业务伙伴的业务，每个模块一个包。只给本仓库引用（Go 的 `internal`）：别的组件编译期就引用不了，跨组件只走契约（决定 0101）。先按下表找到模块，再读那个目录的 `AGENTS.md`。

## 模块

| 包 | 一句话 | 依赖（本组件内） |
| --- | --- | --- |
| `partners` | 伙伴：新建、修改、状态、列表；税号的规范化与查重 | `core` |
| `roles` | 按法人的客户与供应商角色与状态；资格 | `core`、`partners` |
| `source` | 系统面：来源方法、资格查询、批量解析 | `core`、`roles` |
| `core`（共用） | 名字与资源定义、校验、审计与事件、记录、`Base`、本版不做的路由 | — |

分层（每个包只引用比它低的层）：`source` → `roles` → `partners` → `core`。

## 共同的写法

- 每个模块的函数先收 `m *core.Base`（运行时；来源方法盖戳用的部署与实现实例），入口包的 `Module` 持有它、登记时适配。
- 问 `mdm/org` 在事务之外：先取证（`roles` 的 `legalEntityActive`），再在事务里写；`mdm/org` 不可达答依赖不可用，不当作“法人不存在”。
- 写入、审计（`core.Change`）与发件表（`core.Emit`）同一个事务；内容相同不产生新版本（`core.Same`）。
